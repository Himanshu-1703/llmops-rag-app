## ✅ PASS - test_case_1

<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** - Determinism:
  - ML systems: outputs are deterministic. Given the same input (like 2 and 3 to a calculator) you always get the same exact output (5). Evaluation is simple and automated with mathematical formulas or pass/fail tests.
  - LLM apps: outputs are probabilistic and non-deterministic. The same input can produce different, valid outputs (different words, sentence counts, lengths). Simple assertion-based testing fails because there is no single correct string.

- Dynamic cost:
  - ML systems: cost is predictable per dataset/compute. Example from the lecture: 100 rows always cost 10 rupees when hosted on a server.
  - LLM apps: cost is dynamic and hard to fix because both input length and output length drive cost. Input cost and output cost vary per request, so overall cost is difficult to judge.

- Input–output tracking and evaluation:
  - ML systems: relationship between input and output is static and easy to manage; evaluation is cheap and automated.
  - LLM apps: relationship is dynamic — nothing is fixed; outputs are semantically flexible (not exact strings), multiple components (e.g., retriever and generator) can fail independently, and evaluation is costly (text requires detailed, often human judgment). Human annotation doesn’t scale, so you need careful automated or hybrid evaluation approaches and ongoing management of input/output behavior.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.

</details>

- **Actual Output:** Fixed vs. flexible output
- Traditional software: outputs are fixed and deterministic. Same input always yields the same exact output (e.g., 2 + 3 → 5). Tests are simple pass/fail assertions.
- LLMs: outputs are flexible and probabilistic. The same prompt can produce very different but valid responses (different words, lengths, phrasing). Correctness is semantic rather than exact-string, so simple assertion-based testing often fails.

Multi-metric quality (vs. single correctness)
- Traditional software: you mainly measure correctness (did it produce the expected value?).
- LLM-based applications: you must evaluate multiple dimensions, for example:
  - Correctness (is the answer factually right?)
  - Relevance (does the answer address the asked question? e.g., giving underfitting when asked about overfitting is incorrect/relevant)
  - Completeness (is the answer sufficiently thorough?)
  - Grounding (is the answer based on the intended data source, e.g., in a RAG system?)
- Multiple components (retriever, generator) can fail independently, so evaluation must consider component-level issues as well.

Consequences
- There is a grey area rather than binary pass/fail.
- Evaluation is costlier because it often requires text-level judgment; human annotation doesn’t scale, pushing toward automated approaches.
- **Expected Output:** LLM evals are harder than software tests because:

- **Software tests** usually check **fixed, deterministic output** — one input should produce one expected answer, so it’s mostly **pass/fail**.
- **LLM evals** deal with **flexible, probabilistic output** — the same prompt can produce different but still valid answers.

Also, software testing mostly checks **correctness only**, while LLM evals need **multi-metric quality checks** like:
- correctness
- relevance
- completeness
- groundedness
- safety

So, unlike software tests, LLM evals are not just about “right or wrong”; they evaluate whether the answer is good across multiple dimensions.
