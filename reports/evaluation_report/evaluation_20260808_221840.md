<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** Determinism
- Traditional ML / software is deterministic: same input → same output every time (e.g., a regression model returning 10 for a given input).
- LLM apps are probabilistic / non-deterministic: the same prompt can give different outputs on different runs.

Dynamic cost
- In traditional ML the compute/cost is more predictable and tied to dataset size and hosting (e.g., 100 rows on a server has a definable compute cost). Evaluation is cheap and automated.
- In LLM applications costs are more dynamic: multiple components (retriever, generator/LLM) run, outputs are variable, and evaluation requires human judgment and detailed text reports, which is more costly.

Input–output tracking
- In traditional ML you have fixed labels and one main component to evaluate (the model). It’s easy to compare outputs against labels using formulas.
- In LLM apps outputs are complex text where semantic meaning matters. Text can differ while still being correct, so you must actively manage and track the relationship between inputs and outputs, monitor multiple components, and use qualitative judgments rather than simple automated checks.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.

</details>

- **Input:** How can a generator hallucinate despite correct retrieval, and what causes it?
- **Actual Output:** - Even with correct retrieval, the generator can "hallucinate" when it was given the wrong documents or the wrong document ordering to prioritize. If the generator is told to rely on higher-priority docs but those docs contain incorrect or mismatched data, the model will faithfully use that bad info and produce a wrong answer (not inventing facts out of thin air, but mixing up the wrong context).
- The generator can mix pieces from multiple retrieved documents (e.g., combining six weeks of data) and produce an incorrect factual output even though it followed the instructions.
- Output-format or expectation mismatch: you might expect a specific format or specific field, but the generator returns a different form making the result seem wrong.
- Determinism/stochasticity: the same input can give slightly different outputs each run, causing inconsistent or seemingly incorrect answers.
- So causes are wrong documents/prioritization, context mixing, format mismatch, and nondeterministic generation — even when retriever and generator individually appear to work.
- **Expected Output:** A generator can hallucinate even when retrieval is correct by ignoring the retrieved context and producing an answer from its own assumptions or from unrelated parts of the context. This happens because the retriever may fetch the right documents, but the generator can still misread them, over-prioritize certain text, or add unsupported facts.
