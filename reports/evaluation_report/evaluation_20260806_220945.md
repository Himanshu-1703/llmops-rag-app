<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** - Determinism:
  - ML systems: deterministic. Same input -> same output every time (e.g., calculator: 2+3 always = 5). Easy to write pass/fail tests and evaluate with formulas.
  - LLM apps: probabilistic and non‑deterministic. The same input can produce different, but valid, outputs (different words, lengths, formats). Outputs are semantically flexible rather than exact strings, so simple assertion‑based testing often fails.

- Dynamic cost:
  - ML systems: cost is relatively fixed and predictable. Example from context: 100 rows → fixed compute cost (10 rupees).
  - LLM apps: cost is dynamic and hard to fix because both input length and output length vary. You pay for input tokens and output tokens, so total cost fluctuates and is difficult to judge upfront.

- Input–output tracking and evaluation:
  - ML systems: input→output relationship is stable and easy to track; evaluation is cheap and automated (mathematical metrics).
  - LLM apps: relationship is dynamic and must be actively managed. Outputs can be semantically flexible and non‑deterministic; multiple components (e.g., retriever and generator) can fail independently. Evaluation is costly, needs proper judgment and detailed text reports, and human annotation does not scale, forcing more complex automated approaches.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.

</details>

<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do LLM evals differ from software tests in fixed vs. flexible output and multi-metric quality?
- **Actual Output:** - Fixed vs. flexible output
  - Traditional software: outputs are fixed/deterministic. A test is binary — e.g., 2 + 3 must equal 5.
  - LLMs: outputs are probabilistic and semantically flexible. The same prompt can produce very different, yet valid, answers (different words, length, phrasing). Because of this non-determinism, simple assertion-based tests (exact-string checks) don’t work.

- Single-metric vs. multi-metric quality
  - Traditional software: you mostly measure correctness (pass/fail).
  - LLM applications: you must evaluate many dimensions, e.g. correctness, relevance (on-topic), completeness, and groundedness (is the answer based on the provided data vs. hallucination). Multiple system components (e.g., retriever and generator) can fail independently, so you need component-level and multi-dimensional evaluation.
