## ✅ PASS - test_case_1

<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** Determinism
- Traditional ML: deterministic — same input gives the same output (example: calculator 2+3 always = 5). Evaluation is cheap and automated with fixed tests.
- LLM apps: probabilistic/non‑deterministic — the same input can produce different but valid outputs (different wording, length, structure). There is no single correct string, so simple assertion tests often fail.

Dynamic cost
- Traditional ML: cost is stable and predictable (example: 100 rows → fixed cost of 10 rupees).
- LLM apps: cost is dynamic and hard to fix because both input length and output length affect cost. You pay for tokens on both sides, so total compute/cost varies per request.

Input–output tracking
- Traditional ML: relationship between input and output is fixed and easy to verify automatically.
- LLM apps: the input→output relationship is fluid and must be managed and judged. Outputs are semantically flexible, multiple components (e.g., retriever and generator) can fail independently, and evaluating text outputs is costly and often requires human judgment or complex automated metrics.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.

</details>
