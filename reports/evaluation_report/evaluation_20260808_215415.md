- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** Determinism
- Traditional ML: outputs are deterministic. Same input gives the same output every time (like 2+2 = 4). Evaluation is done with fixed mathematical formulas.
- LLM apps: outputs are probabilistic and non‑deterministic. The same prompt can produce different, yet valid, answers. There is no single “right” string.

Dynamic cost
- Traditional ML: evaluation is cheap and automated; cost is relatively stable for prediction/evaluation.
- LLM apps: cost and compute are dynamic. Compute used (and cost) changes with the input, the output, the retrieved context, and the workflow length/complexity. More data or more workflow steps increases cost.

Input–output tracking
- Traditional ML: for simple prediction there is usually no need to track the full input→output journey or a multi‑step workflow.
- LLM apps: there is a workflow that can vary in number of steps and complexity. You must track and evaluate those steps, and different components (e.g., retriever vs generator) can fail independently, making tracing and evaluation more important and harder. Evaluation often requires human judgment and detailed reports, which is costly and hard to scale.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.
