## ✅ PASS - test_case_1

<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** Determinism
- Traditional ML systems are deterministic: same input -> same output (example: calculator 2+3 always =5).  
- LLM apps are probabilistic and non-deterministic: the same input can produce different, but valid, outputs. Outputs are semantically flexible (different words/paragraphs can all be correct). Simple assertion-based tests that expect exact strings will fail.

Dynamic cost
- Traditional ML: compute/cost is roughly fixed per data size. Example: 100 rows -> cost = 10 rupees when hosted on a server.  
- LLM apps: cost is dynamic and hard to fix because both input length and output length matter. You pay for input tokens and output tokens; evaluation itself is more costly (text outputs need detailed, often human, judgment).

Input-output tracking
- Traditional ML: easy to track inputs to outputs; evaluation can be automated with mathematical formulas.  
- LLM apps: you must manage a changing relationship between input and output because nothing is static. Outputs are variable and semantically flexible, so you need richer evaluation (detailed reports, component-level checks). Multiple components (e.g., retriever and generator) can fail independently, so tracking must handle those separate failure modes. Human annotation doesn’t scale, pushing toward automated but more complex approaches.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.

</details>

## ✅ PASS - test_case_12

<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do LLM evals differ from software tests in fixed vs. flexible output and multi-metric quality?
- **Actual Output:** - Fixed vs flexible output
  - Traditional software: deterministic. A given input has one fixed correct output (e.g., 2+3 must equal 5). Tests are simple pass/fail based on exact match.
  - LLMs: probabilistic and non‑deterministic. The same input can produce many different but valid outputs (different words, lengths, styles). Outputs are semantically flexible, so correct answers may not be exact string matches. This breaks simple assertion-based testing and requires evaluations that accept semantic equivalence.

- Multi‑metric quality vs single correctness
  - Traditional software: you mostly measure correctness only (is the output right or wrong).
  - LLMs: you must test many quality dimensions, e.g. correctness, relevance, completeness, groundedness (is the answer based on provided data or invented?).
