## ✅ PASS - test_case_1

<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** - Determinism
  - Traditional ML: outputs are deterministic. Same input → same exact output (example: a calculator always returns 5 for 2+3). Evaluation is simple, formulaic and assertion-based.
  - LLM apps: outputs are probabilistic and non-deterministic. Same input can produce different, valid outputs (different wording, length, etc.), so simple pass/fail tests often don’t work.

- Dynamic cost
  - Traditional ML: compute cost per fixed data size is predictable and can be fixed (example: 100 rows → cost 10 rupees).
  - LLM apps: cost is dynamic because both input length and output length matter (input cost + output cost). You cannot fix the cost easily; evaluation and generation costs vary.

- Input–output tracking and evaluation
  - Traditional ML: input→output relationship is stable and easy to track; evaluation is cheap and automated (mathematical checks).
  - LLM apps: relationship is dynamic and must be actively managed. Outputs are semantically flexible (not exact strings), multiple components (e.g., retriever and generator) can fail independently, and evaluating text output needs judgment, detailed reports, and often costly human annotation (which doesn’t scale), so automated evaluation is harder.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.

</details>

## ✅ PASS - test_case_12

<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do LLM evals differ from software tests in fixed vs. flexible output and multi-metric quality?
- **Actual Output:** - Fixed vs flexible output
  - Traditional software: outputs are fixed and deterministic. A given input yields one correct string (e.g., 2 + 3 always = 5). Tests are simple assertions that either pass or fail.
  - LLMs: outputs are flexible and probabilistic. The same input can produce very different, yet valid, answers (different words, length, phrasing). Outputs are semantically flexible — similar but not identical strings can both be correct. Because of non-determinism, simple assertion-based tests often fail.

- Multi-metric quality vs single correctness
